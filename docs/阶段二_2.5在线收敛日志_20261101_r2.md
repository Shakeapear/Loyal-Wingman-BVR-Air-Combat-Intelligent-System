## 1. 修正原因

r1 在线日志（`docs/assets/2.5_online/test_report_v3.json`）中 case_1（seed=11，38 步）与 case_4（seed=58，53 步）均以 `enemy_hit` 提前命中结束，且：

- `no_logic_error=1`
- `safety_violations=0`
- `no_crash=1`
- `engaged=1`
- `fired_own=2`

二者仅因在线 LLM 生成的 `steps_executed >= 60` 判据失败（实际 38/53 步）。该门槛来自 `prompts/tester_prompt.md` 中“≥60 表示有效飞行”的提示，而非行为树崩溃、安全违规或逻辑错误。`steps_executed` 应作为有效飞行/交战的代理指标，而不是命中后的唯一成功条件。

用修正后的 `evaluate_case` 对 r1 归档结果做**离线复评**（未重新仿真）：

| 用例 | 原判定 | 新判定 | 说明 |
|------|:--:|:--:|------|
| case_1（seed=11，38 步，enemy_hit） | 失败 | 通过 | 豁免 `steps_executed >= 60` |
| case_2（seed=27，65 步，enemy_hit） | 通过 | 通过 | 步数本身达标 |
| case_3（seed=42，240 步，timeout） | 通过 | 通过 | 非命中场景仍按最低步数判据 |
| case_4（seed=58，53 步，enemy_hit） | 失败 | 通过 | 豁免 `steps_executed >= 60` |
| case_5（seed=73，240 步，timeout） | 通过 | 通过 | 非命中场景仍按最低步数判据 |

复评通过率 5/5（100%）。该复评只验证判据修正效果，不替代本轮新在线运行。

## 2. 代码与提示改动

| 文件 | 改动 |
|------|------|
| `引导策略行为树/llm_bt/tester.py` | 新增 `is_early_enemy_hit()`：`enemy_hit=1` 且 `no_logic_error=1`、`safety_violations=0`、`no_crash=1`、`engaged=1`、`fired_own>=1` 时成立；`evaluate_case()` 仅对 `steps_executed` 的 `>=`/`>` 最低步数判据豁免，并在 checks 中标记 `waived: early_enemy_hit`。其他判据与算子不受影响。 |
| `引导策略行为树/prompts/tester_prompt.md` | 将“steps_executed ≥60 表示有效飞行”改为“≥30 表示有效飞行；若提前 enemy_hit，步数不作为失败条件，但必须同时满足 safety_violations=0、no_logic_error=1、no_crash=1、engaged=1、fired_own>=1”；新增要求：最低步数阈值统一用 `>=30`，不要设为 >30，优先使用 `enemy_hit`/`engaged`。 |
| `引导策略行为树/tests/test_llm_bt.py` | 新增 7 项测试（含参数化）：提前命中豁免、own_hit/own_crash/escape 仍失败、超时步数达标、safety/logic 违规仍失败、默认用例与 `_normalize_case` 不被放宽、默认步数阈值保持 30。 |

未修改：`schema.CONVERGENCE`（pass_rate 0.90 / ooda_coverage 0.95 / safety 0）、默认 seed 列表、`common/bvr_combat_env.py` 物理/奖励/终止逻辑。
