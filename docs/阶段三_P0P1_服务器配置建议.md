# 阶段三 P0/P1 服务器配置与费用建议

> 日期：2026-11-01　｜　币种：人民币（USD 按 1 USD≈7.2 CNY 折算，仅估算）
> 状态：**已完成本地 pilot 与 CPU/GPU 选型分析；尚未租用任何实例，等待用户确认平台、区域、预算与最长时长后再启动长训练。**
> 价格来源为公开页面/第三方汇总，未含税、磁盘、公网流量；实际以云控制台实时报价与库存为准。

## 1. 结论先行

| 问题 | 结论 |
|------|------|
| 租 CPU 还是 GPU？ | **优先 CPU**：16 vCPU / 32 GB，8 个 `SubprocVecEnv` 并行 JSBSim。 |
| 为什么不用 GPU？ | 网络仅约 4 万参数；实测单步仿真 1.057 ms（946 steps/s 单环境），混合网络前向+采样+反传可达约 13.3 万样本/s，瓶颈在 JSBSim/Python 环境而非矩阵运算。GPU 会长期空闲。 |
| 推荐平台 | 1) 腾讯云 SA3.4XLARGE32；2) 阿里云 u2a/c7 16C32G；3) AWS c6i.4xlarge（Spot）。 |
| 预算量级 | P0+P1 各 1e7 步，两套合计约 **24–40 h**，CPU 费用约 **¥55–200**（不含公网/存储小额费用）。 |
| 需要用户确认 | 平台/区域、预算上限、最长租用时长、是否可用境外支付、是否允许 Spot 中断。**确认前不租用、不启动 1e7。** |

## 2. CPU/GPU 实测与判断

### 2.1 本地基准环境

| 项 | 值 |
|----|----|
| CPU | Intel Core i7-14700HX，20 核 / 28 线程 |
| 内存 | 31.7 GB |
| OS | Windows 11（开发机，非服务器） |
| Python | 3.12（conda DC） |
| torch / SB3 / gym | 2.13.0+cpu / 2.9.0 / 1.3.0 |
| 场景 | strike，80–120 km，600 步，`control_mode=assisted` |

### 2.2 20k 步 pilot 吞吐

| 策略 | 并行方式 | 20k 步 wall | steps/s | 1e6 步估算 | 1e7 步估算 |
|------|----------|--:|--:|--:|--:|
| P1 hybrid | DummyVecEnv×8（串行） | 172.65 s | 115.8 | 2.40 h | 24.0 h |
| P0 mlp | DummyVecEnv×8（串行） | 153.56 s | 130.2 | 2.13 h | 21.3 h |
| P1 hybrid | SubprocVecEnv×8 | 118.00 s | 169.5 | 1.64 h | 16.4 h |
| P0 mlp | SubprocVecEnv×8 | 99.72 s | 200.6 | 1.39 h | 13.9 h |

### 2.3 组件微基准

| 组件 | 实测 | 含义 |
|------|------|------|
| 单环境 `env.step`（安全平飞，600 步场景，`compute_envelope=False`） | 1.057 ms/step（946 steps/s） | JSBSim 是主要成本 |
| Hybrid 网络 batch=256 前向 | 44.3 万样本/s | 网络极轻 |
| Hybrid 网络 batch=256 前向+采样+log_prob+反传 | 13.3 万样本/s | 训练更新不是瓶颈 |
| 8 环境 Subproc 端到端 | 169–201 steps/s | 受环境/进程 IPC/reset 影响，远低于单环境×8 |

**判断**：GPU 对端到端吞吐的提升上限受 Amdahl 定律限制；在 JSBSim 仍跑 CPU 的前提下，GPU 加速比预计 **<1.5×**，且 GPU 实例单价更高、CPU 核数更少。**推荐 CPU 16 vCPU/32 GB**；GPU 仅在后续把环境向量化到 GPU（本项目未做）时才值得重新评估。

> 说明：本轮未租用 GPU 实例，因此没有 GPU 实例上的 steps/s 实测；这是遵守“未确认不擅自租用”的约束。上表 GPU 结论来自组件微基准与架构分析，已明确标注，不冒充实测。

## 4. 推荐方案（按推荐度）

### 方案 A（首选）：腾讯云 SA3.4XLARGE32，16 vCPU / 32 GB

- **区域**：广州/北京/上海（选库存充足、离用户近的可用区）。
- **配置**：16 vCPU/32GB，Ubuntu 22.04/24.04，系统盘 100 GB SSD，公网按流量（训练仅回传日志/模型，流量很小）。
- **运行方式**：8 个 `SubprocVecEnv`，P0/P1 各 1e7 步，训练 seed 0，评估 seeds 1–20。
- **预估时长**：按 150–250 steps/s 加 10–20% 评估开销，约 **12–20 h/策略**，两套 **24–40 h**。
- **预估费用**：¥1.88/h × 24–40 h ≈ **¥45–75**；加 100GB 云盘与少量流量约 **¥55–90**。
- **优点**：单位小时最低、国内延迟低、CPU 核数满足 8 并行；缺点：库存/活动价需下单页确认，阶梯价规则需核对。
- **启动命令**：见 §6 与 `docs/阶段三_P0P1_训练命令清单.md`。

### 方案 B：阿里云 u2a（16C32G）或 c7.4xlarge

- **配置**：u2a 16C32G（¥2.19/h）优先；若需 Intel 稳定单核选 c7.4xlarge（¥3.26/h）。
- **预估时长/费用**：24–40 h；u2a **¥52–88**，c7 **¥78–130**（不含磁盘/流量）。
- **优点**：控制台/生态成熟、国内区域多；缺点：同规格单价高于腾讯 SA3，u2a 库存需确认。
- **适用**：已有阿里云账号/余额，或腾讯 SA3 无库存时。

### 方案 C：AWS c6i.4xlarge（Spot 优先，us-east-1）

- **配置**：16 vCPU/32GB，Ubuntu 22.04，gp3 100GB；Spot 需容忍中断并依赖 checkpoint/resume。
- **预估时长/费用**：24–40 h；On-Demand $16–27（≈¥117–196），Spot $7–16（≈¥50–115），加 EBS 约 $1。
- **优点**：规格稳定、Spot 便宜、工具链成熟；缺点：国内访问延迟、需国际支付、Spot 可能中断（每 1000 episode checkpoint + `--resume` 可恢复）。
- **适用**：可接受境外区域与 Spot 中断，追求弹性。

### GPU 备选（不推荐作为首选）

- 腾讯云 GN7 T4（8C32G，$0.204/h）或 RunPod 4090（$0.34/h）价格看似低，但 CPU 核数少/不稳定，GPU 对本项目基本闲置；预计端到端不优于 16C CPU。仅在 CPU 实例长期无库存时作为兜底，并需重新实测 steps/s。

## 5. 费用与时长假设

| 假设 | 取值 |
|------|------|
| 单策略步数 | 1e7（先跑 1e6 pilot 确认曲线再继续） |
| 并行 | 8 envs，SubprocVecEnv |
| 端到端吞吐 | 150–250 steps/s（CPU 16C，含 PPO 更新） |
| 评估开销 | 每 500 episode × 20 seeds，约 +10–20% wall |
| 两策略总时长 | 24–40 h |
| 存储/流量 | 100GB SSD + 模型/日志/ACMI 回传，约 ¥10–20 |
| 价格有效期 | 2026-11-01 公开页；下单前以控制台为准 |

**预算建议**：准备 **¥150–250** 作为 CPU 方案含缓冲（两套训练 + pilot + 可能的第二次重跑）；若选 AWS On-Demand 或需要 GPU 兜底，准备 **¥300–500**。

## 6. 启动前需要用户确认

1. 平台与区域（腾讯云/阿里云/AWS；国内/境外）；
2. 预算上限（建议 ≥¥250，含重跑缓冲）与最长租用时长（建议 ≥48 h）；
3. 是否接受 Spot/抢占式中断（是则依赖 checkpoint/resume）；
4. 是否已有实例/账号/余额；是否需要我们生成开机初始化脚本；
5. 是否允许把模型/日志打包回传（不含密钥）。

**在收到上述确认前，不租用实例、不启动 1e7 长训练。** 当前仅完成代码、场景、固定测试集、20k pilot 与选型建议。
