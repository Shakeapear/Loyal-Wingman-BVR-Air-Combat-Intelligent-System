## 一、为什么需要这批数据（采集目的）

后期智能体训练需要三类数据，**现在就能储备前两类**：

| 用途 | 数据内容 | 对训练的作用 |
|------|---------|------------|
| **① 飞行技能演示数据**（本规范主产） | 专家轨迹：状态 + 动作 + 阶段标签 | 行为克隆（BC）预热策略；JSRL 引导策略动作模仿；机动动作库 |
| **② 平台能力基准数据** | 巡航/爬升/盘旋/下降的边界包线 | 性能约束标定、奖励函数标定、飞行包线验证（计划书步骤 2.1/2.4） |
| **③ 空战博弈数据**（后期由 Gym 环境产生） | 含目标/导弹/奖励的完整 episode | PPO/JSRL 正式训练（阶段三） |

> 现在采集的轨迹**不含目标与武器信息**（JSBSim 单机仿真），这没问题：飞行技能数据在行为克隆与引导策略训练中永远需要，采集得越多，训练启动越快。空战博弈数据格式是本文档格式的**扩展**（追加目标/武器列即可），字段基础完全一致。

**一条轨迹（episode）= 一段完整飞行过程的状态-动作序列**。样例 `f104_demo_ep0001.csv` 是一段 180 秒、6 个阶段的机动飞行（巡航→右盘旋→爬升→左盘旋→下降→巡航）。

---

## 二、文件格式规范（trajectory_v1）

- **一个文件 = 一个 episode**，文件内每行 = 一个决策步（默认 1 Hz）；
- 文件开头是 9 行以 `#` 开头的**元数据**，随后是 1 行**表头**，再是数据行；
- 59 列 = 6 列身份/标签 + 4 列动作与派生量 + 47 列状态 + 2 列自驾仪原始指令（合计 59）；
- 编码 UTF-8，分隔符逗号，6 位小数；
- pandas 直接读取：`pd.read_csv(文件, comment='#')`（自动跳过元数据）。

## 三、样例文件逐部分讲解

### 3.1 元数据头（第 1-9 行）

```
#format: trajectory_v1         ← 格式版本，训练代码据此解析
#episode_id: f104_demo_ep0001  ← 全局唯一回合编号
#aircraft: f104                ← 机型
#scenario: S3                  ← 场景编号（见《04》附录 A 场景卡）
#task_label: flight_skill_demo ← 任务标签（训练时按此筛选数据）
#collector: 唐煜皓             ← 采集人
#script: scripts/f104_training_demo.xml ← 生成数据的脚本（可追溯）
#rate_hz: 1.0                  ← 采样率
#jsbsim_version: 1.2.4         ← 引擎版本
```
作用：训练代码据此自动分拣数据、追溯来源；人看也能一眼知道这份数据是什么。

### 3.2 身份与标签列（第 1-5 列）

| 列 | 样例值 | 含义 |
|----|--------|------|
| `episode_id` | f104_demo_ep0001 | 回合编号（与元数据一致） |
| `step` | 0…179 | 决策步序号，从 0 开始 |
| `t_s` | 0.0…179.0 | 仿真时间（秒） |
| `task_label` | flight_skill_demo | 任务标签，整条轨迹相同 |
| `phase_label` | cruise/turn_right/turn_left/climb/descend | **每步的阶段标签**（自动推导，见 §3.5） |

`phase_label` 是这条数据的灵魂：训练时可按阶段分段（如只取 climb 段训练爬升策略）、可统计阶段占比、可给行为克隆加阶段条件。

### 3.3 动作列（第 6-8 列）——智能体要学的东西

| 列 | 样例值 | 含义 | 单位 |
|----|--------|------|------|
| `action_roll_cmd_rad` | 0.5236 | 滚转角指令（专家决策：滚多少度坡度） | rad（正=右滚） |
| `action_alt_cmd_m` | 4572.0 / 5334.0 | 高度指令（专家决策：飞到多高） | m |
| `action_speed_cmd_mps` | 228.6 | 速度指令（专家决策：飞多快） | m/s |

**这三列就是"专家动作"**——相当于飞行员脑子里下达的"指令"，行为克隆/引导策略要学习的就是 `状态 → 这些指令` 的映射。它们由自驾仪（`autopilot-hold`）执行，实际舵面/油门输出在状态列里（`throttle/elevator/aileron/rudder`），构成完整的"决策→执行"记录。

### 3.4 派生量与终止标志（第 9-10 列）

| 列 | 含义 | 单位 |
|----|------|------|
| `gamma_deg` | 航迹倾角（爬升为正、下降为负，由垂直/水平速度算出） | deg |
| `done` | 终止标志：最后一步为 1，其余为 0 | 0/1 |

`done=1` 标记 episode 结束，训练代码按它切分序列。

### 3.5 状态列（第 11-57 列，共 47 列）

即《03 字段字典》的完整 47 列标准状态（高度/位置/速度/姿态/迎角/过载/操纵面/推力/燃油/质量/大气）。样例节选（实际文件数据，保留 3 位小数）：

```
step  phase_label   h_sl_m  vtrue_mps  phi_rad  theta_rad  alpha_rad  nz_g  throttle  gamma_deg
  50  turn_right  4457.301   226.983    0.525     0.088      0.076    1.081    0.849     1.159
  71  climb       4466.026   226.730    0.263     0.161      0.148    2.112    0.876     1.312
 120  turn_left   5200.458   228.087   -0.525     0.079      0.091    1.185    0.812    -0.124
 152  descend     4747.060   240.095    0.005    -0.156      0.075    1.210    0.000   -13.249
```
物理含义示例：右盘旋时坡度 +30°（0.525 rad）、过载 1.08 g；爬升拉杆时俯仰角 +9.2°（0.161 rad）、过载 2.11 g、油门 0.88；下降段油门收到 0、航迹倾角 -13.2°、速度因俯冲增至 240 m/s。**状态与动作互相印证，这就是专家行为的完整记录。**

### 3.6 自驾仪原始指令列（第 58-59 列）

| 列 | 含义 |
|----|------|
| `fcs/ap-roll-setpoint-rad` | 滚转角指令原值（= action_roll_cmd_rad 的原值） |
| `fcs/ap-alt-setpoint-ft` | 高度指令原值（ft） |
| `fcs/ap-speed-setpoint-fps` | 速度指令原值（fps） |

保留原值便于核对与重新推导；训练代码只用第 6-8 列的 SI 动作列。

### 3.7 样例轨迹的阶段时间线

| 步数 | 时间 | 阶段 | 动作变化 | 数据特征 |
|------|------|------|---------|---------|
| 0-29 | 0-30 s | cruise | 高度指令 4572 m、速度 228.6 m/s | 定高定速，γ≈-1° |
| 30-69 | 30-70 s | turn_right | 滚转指令 +0.5236 rad | φ→+30°，ψ 匀速转 46°，nz≈1.1 |
| 70-99 | 70-100 s | climb | 滚转 0、高度指令 5334 m | γ≈+5~7°，nz≈2.1，油门≈1 |
| 100-139 | 100-140 s | turn_left | 滚转指令 -0.5236 rad | φ→-30°，反向盘旋 |
| 140-152 | 140-153 s | descend | 高度指令回 4572 m | γ≈-3~-13°，油门≈0，推杆 |
| 153-179 | 153-180 s | cruise | 保持 | 恢复到定直平飞 |

## 四、这份数据将来怎么被训练代码使用

```python
import pandas as pd
df = pd.read_csv("样例数据/f104_demo_ep0001.csv", comment='#')   # 自动跳过元数据

# 1. 状态（obs）：取状态列子集，将来 obs 空间从这里选
obs_cols = ["h_sl_m","vtrue_mps","mach","phi_rad","theta_rad","psi_rad",
            "alpha_rad","beta_rad","nz_g","throttle","fuel_lb"]
obs = df[obs_cols].to_numpy(dtype=float)

# 2. 专家动作（guide action）：智能体要模仿的决策
acts = df[["action_roll_cmd_rad","action_alt_cmd_m","action_speed_cmd_mps"]].to_numpy(dtype=float)

# 3. 行为克隆样本：(obs[t], acts[t]) 一一对应；done 用于切分 episode
# 4. 阶段标签用于分段训练/课程学习：
climb_idx = df.index[df.phase_label == "climb"]
```

## 五、组员采集流程（照做即可）

**第 1 步 领任务**：从 §六 采集清单中认领场景，拿到场景卡（《04》附录 A 模板）。
**第 2 步 改脚本**：复制 `JSBSim\scripts\f104_training_demo.xml`，只改：
- 文件名（`<output name>`）；
- 各阶段事件的 `<condition>` 时刻与 `<set>` 指令值（滚转角/高度/速度）；
- **标准事件块（燃油/发动机/收轮/自驾仪接通）一行不许动**（《04》§3）。
**第 3 步 跑仿真**：
```
& ".\JSBSim\JSBSim.exe" --root=".\JSBSim" --script="scripts\你的脚本.xml"
```
**第 4 步 生成轨迹文件**：
```
py "JSBSim_培训与验证资料\tools\make_trajectory.py" "JSBSim\你的_raw.csv" "数据采集\Sx_场景\f104_Sx_日期_序号.csv" --episode f104_Sx_日期_序号 --scenario Sx --task 任务标签 --collector 你的名字
```
**第 5 步 自查后提交**：按《04》§6 质量检查逐项核对（行数 = 时长×采样率+1、59 列齐全、无坠地、命名合规、记录表齐全），压缩后交徐文强验收。

## 六、采集清单（储备任务，全员分领）

**A 组：巡航包线**（task_label: cruise）——高度 × 速度网格，每条 120 s：

| 高度 | 速度（fps） | 每人采集数 |
|------|------------|:---:|
| 10000 ft | 600 / 700 / 800 | 各 3 条 |
| 15000 ft | 650 / 750 / 850 | 各 3 条 |
| 20000 ft | 700 / 800 / 900 | 各 3 条 |

**B 组：盘旋包线**（task_label: turn）——坡度 × 方向，每条 120 s：坡度 15°/30°/45° × 左/右 × 高度 10000/15000 ft，共 12 组，每组 2 条。

**C 组：爬升/下降包线**（task_label: climb_descent）——10000→20000 ft 与 20000→10000 ft，速度 700/800 fps，各 2 条，每条 150 s。

**D 组：组合机动**（task_label: flight_skill_demo）——参照样例（巡航+双盘旋+爬升+下降），每人不限数量，越多越好，每条 180 s。

**总量目标：** 全组 ≥ 200 条轨迹（约 8-10 小时采集工作量，脚本运行本身每秒可完成多条，大头是配置与记录）。

## 七、易错提醒

1. **改脚本时不要动**：标准事件块、`dt`、`rate="10"`、机型与初始化文件名；
2. **每条轨迹换一个输出文件名**，否则互相覆盖；
3. **元数据要真实**：`--collector`、`--scenario`、`--task` 与场景卡一致，训练代码按这些字段筛数据，错了会污染数据集；
4. **t=0 行是配置前状态**（燃油 7000 lb、无指令），训练时一般从 step ≥ 1 使用；
5. 任务标签用英文小写、下划线分隔（`cruise`、`turn`、`climb_descent`、`flight_skill_demo`），全组统一。
